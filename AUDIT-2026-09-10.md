## 🟡 MEDIUM

### M1. Ephemeral Tailscale identity churn (root cause of today's 15-min hang)
- `TAILSCALE_AUTH_KEY` creates **ephemeral** nodes → node record auto-deleted after offline → every boot = brand-new node record (name `-N` suffix) + IP re-pin + cleanup dance. Works today (pin succeeded 16:01Z) but fragile: one failed pin-API call (e.g. HTTP 500 while IP held) ⇒ server on a **new IP**.
- Better steady state: create a **non-ephemeral** auth key (no expiry) → node record persists across reboots → `tailscale up` re-attaches the *same* node (same id/name/IP), no churn, pin becomes a safety net only. One-time change: new key in console (no "Ephemeral" flag) → update `TAILSCALE_AUTH_KEY` secret.

### M2. `--accept-routes` advertises the runner's internal subnet to the tailnet
- The node advertises the GitHub runner's VPC subnet (172.x); tailnet devices get routes into GitHub infrastructure. Not needed for SSH access.
- Fix: drop `--accept-routes` from `tailscale-setup.sh` + keepalive watchdog unless something actually routes through.

### M3. Successor chain depends on the exposed PAT
- `SUCCESSOR_TOKEN` = the chat PAT. Rotate the PAT without updating the secret ⇒ chain dies at next handoff (hourly schedule backstop rescues within 1h).
- Improvement: dispatch the successor with `github.token` (job already has `permissions.actions: write`) ⇒ eliminates one long-lived exposed token from the chain.

### M4. Rolling single snapshot — no history/rollback
- `state_sync.py` purges the previous asset right after the new one verifies. A logic bug + bad timing = data loss with no fallback.
- Optional: keep last N (2-3) snapshots (download still picks newest).
